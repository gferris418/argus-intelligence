# ARGUS Intelligence v2.0.1 Release Decision

**Date:** 2026-10-20  
**Channel:** stable  
**Status:** RELEASED  
**Predecessor:** 2.0.1-rc.1 on ARGUS `main` before this promotion
**Validated ATLAS:** 2.0.1 at `b8b8559c57eef5fbb97d914d924077ba20b1883d`

## Verification basis

ARGUS `2.0.1-rc.1` introduced the ATLAS `1.2.0` domain-context handoff, `1.0.0` execution-lease contract, `1.0.0` lifecycle-governed signing-key registry, and the corresponding result/retry/resume correlation hardening. The candidate passed the full 188-test contract suite after merge and the credentialed ATLAS↔ARGUS cross-repository E2E path in both `main`-push and same-repository pull-request contexts.

ATLAS was then promoted independently to stable `v2.0.1` at `b8b8559c57eef5fbb97d914d924077ba20b1883d` after protected PR validation, post-merge validation with deterministic snapshot generation, and a successful tag-triggered release workflow. This ARGUS release repins the unchanged ATLAS runtime/contract hashes to that exact stable commit and promotes only the ARGUS product/release identity and compatibility assertions.

## Public-repository transition

Both repositories are public at release time. ARGUS therefore removes the obsolete `ATLAS_SSH_KEY` dependency from its cross-repository E2E checkout. The repository continues to prohibit committed secrets and raw source/tender/email payloads. The manifest and active alignment contract no longer describe the GitHub canonical store as private.

A targeted pre-release search found no committed OpenSSH/private-key markers or common GitHub/OpenAI token prefixes. GitHub's first-party secret-scanning alert endpoint is disabled on this repository, so that targeted search is evidence of absence for those patterns only, not a substitute for full secret scanning.

## Publication gate

Before `v2.0.1` is tagged, the protected release PR must pass the full `contract-tests` workflow and the cross-repository E2E workflow against exact ATLAS commit `b8b8559c57eef5fbb97d914d924077ba20b1883d`. After merge, both workflows must pass again on `main`. The semantic tag and GitHub release are created only after those checks succeed.
