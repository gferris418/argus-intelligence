# ARGUS 3.0.0-rc.2

**Status:** Candidate  
**ATLAS compatibility:** ATLAS-OS 3.0.1  
**Pinned ATLAS commit:** `7ff95f5c96685ec4e7ed7b1eb6fea0821e7e2abc`

## Purpose

ARGUS 3.0.0-rc.2 replaces the stale active ATLAS 2.x integration seam with the ATLAS-OS 3 bounded-provider model without changing ARGUS's commercial-intelligence mission or Access Asia data ownership.

## Current integration

- ATLAS owns `Understand + Normalize -> Minimal Domain Framing -> Route`.
- ARGUS is the provider for semantic capability `intelligence_collection`.
- Current route mechanisms are `ARGUS` and `MULTI_CAPABILITY`.
- `ARGUS_ACTIVATION` requires explicit user approval before execution.
- ARGUS performs one bounded collection mission and returns the provider result to ATLAS.
- ATLAS performs provider-return reconciliation and owns every subsequent step, verification, persistence authorization and delivery.
- Direct factual retrieval remains under ATLAS direct search/research when structured intelligence collection is unnecessary.

## Compatibility

The prior signed ATLAS 2.x handoff, execution-lease, synchronization receipt and replay-protection contracts remain committed and tested as **backward-compatibility-only** evidence. They are no longer the current integration authority.

## Runtime and CI

The current provider adapter is `tools/atlas_v3_provider.py`. Cross-repository CI checks out the immutable ATLAS-OS 3.0.1 commit and exercises the actual ATLAS runtime through approval gating, ARGUS provider execution, provider return and ATLAS reconciliation. The test is read-only: it performs no external collection and no registry writes.

## Storage boundary

No storage authority changes are introduced. GitHub remains the schema, governance, migration and release/audit source. The Access Asia SharePoint SQLite registry remains the current mutable ARGUS commercial state under the existing single-writer protocol.
