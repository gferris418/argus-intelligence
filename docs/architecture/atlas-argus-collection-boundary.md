# ATLAS–ARGUS collection boundary

## Fixed architecture

ATLAS OS is the operating architecture. Mission Control is the human command boundary; the Control Plane owns authoritative machine governance; the Data Plane performs substantive work; Domain Context Services owns canonical semantics and classification; Assurance/Verification checks results; Observability produces operational state; the Dashboard is a read-only projection.

ARGUS is nested inside ATLAS as the governed government commercial opportunity intelligence subsystem. It is not a peer operating system and does not own Mission Control, Control Plane authority, approvals, authoritative pursuit decisions, persistence authorization or final delivery.

```text
Human
  -> Mission Control
  -> ATLAS Control Plane
  -> Input / Intent / Target Interpretation
  -> Collection-Need Gate
       -> NONE
       -> ATLAS_DIRECT
       -> ARGUS_COLLECTION -> ARGUS evidence + commercial opportunity intelligence package
       -> HYBRID           -> ARGUS package + ATLAS substantive analysis/decision
  -> ATLAS Domain Context Services
  -> ATLAS Data Plane analysis / authoritative business decision
  -> Assurance / Verification
  -> Output / Persistence
  -> Observability
  -> Dashboard
```

## Core activation rule

The activation question is not `Is this intelligence?` It is `Does this ATLAS task require structured intelligence collection?`

Examples:

| Request | Collection mode |
| --- | --- |
| Bangladesh Bank foreign exchange policy | ATLAS_DIRECT |
| ST Engineering | ARGUS_COLLECTION |
| Coastal patrol vessel for Bangladesh Coast Guard | ARGUS_COLLECTION |
| Seed cum cleaner for BADC | ARGUS_COLLECTION |
| Annual procurement plan of Bangladesh Navy | ARGUS_COLLECTION |
| Compare ST Engineering vs L3Harris for Bangladesh opportunities | HYBRID |
| Where could a foreign technology solve an unmet Bangladesh government need? | ARGUS_COLLECTION |
| Rank suitable OEMs for an existing government opportunity and recommend pursuit | HYBRID |

## Responsibility split

ARGUS owns the bounded intelligence-domain work needed to establish the commercial opportunity landscape: find, collect, acquire, extract, normalize, resolve, deduplicate, corroborate, expose gaps/conflicts, maintain pre-PX opportunity identity and lifecycle, construct supplier universes, assess partnerability, calculate supplier matches, calculate advisory opportunity qualification, track early-warning events and package the evidence.

ATLAS owns the operating and decision authority: understand the user objective, govern permissions and scope, classify canonically, plan execution, accept/reject canonical evidence status, perform final cross-domain analysis and forecasting, set authoritative opportunity priority, authorize `PROMOTE_TO_PX`, decide pursuit and bid/no-bid, authorize external actions, verify, persist and deliver.

The practical rule is:

> ARGUS may calculate and recommend; ATLAS authorizes and decides.

`PROMOTE_TO_PX`, external customer/OEM engagement, bid/no-bid and other Access Asia pursuit decisions remain ATLAS/business-policy decisions. ARGUS returns the opportunity, supplier, qualification and evidence package needed to make those decisions.

## Commercial opportunity boundary

ARGUS v3 treats `OPPORTUNITY` as the primary commercial intelligence object before a PX identity exists. A persistent pre-PX opportunity may use `ARGUS-OPP-YYYY-NNNNNN`; the Access Asia `YYYY_PXNNNNN_SHORTNAME` identity is assigned only after ATLAS-authorized promotion.

A tender is an event or linked procurement object, not the definition of the opportunity. One opportunity may span planning, funding, multiple packages, tender amendments, rebids, awards and follow-on procurements without changing its ARGUS identity.

Opportunity stage (`S0`–`S9`), commercial mode (`SHAPE`, `POSITION`, `REACT`, `EXPAND`), evidence confidence, procurement realization probability, Access Asia success probability and supplier-match confidence remain distinct dimensions.
